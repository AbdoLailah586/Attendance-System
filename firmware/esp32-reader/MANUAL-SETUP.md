# توصيل وتشغيل قارئ الحضور — Firmware 1.4.0

الاختبار على [المنصة المنشورة](https://attendance-system-joe-2026.vercel.app/). الجهاز ESP32 DevKit الكلاسيكي وRC522 ‏13.56MHz وكروت MIFARE. الشاشة أُزيلت؛ افصل الكهرباء قبل فصل أسلاكها أو تغيير الدائرة.

## 1. توصيل RC522

- 3.3V → **3V3 فقط، وليس 5V**.
- GND → GND.
- SDA / SS → GPIO21.
- SCK → GPIO18.
- MOSI → GPIO23.
- MISO → GPIO19.
- RST → GPIO22.
- IRQ غير موصل.

SDA على RC522 هنا SPI chip select. الأسلاك قصيرة والأرضي مشترك. راجع [توثيق المكتبة](https://github.com/miguelbalboa/rfid#pin-layout) و[بيانات MFRC522](https://www.nxp.com/docs/en/data-sheet/MFRC522.pdf).

## 2. الصفارة والليدات

راجع [BUZZER-LEDS.md](BUZZER-LEDS.md) لتوصيل الصفارة 5V عبر ترانزستور ودايود وتحديد أطراف الترانزستور. لا توصل حمل الصفارة مباشرة بـGPIO.

- الأخضر GPIO13: حضور معتمد من السيرفر.
- الأصفر GPIO33: Refresh؛ يومض أثناء انتظار تأكيد القراءة.
- الأحمر GPIO14: انصراف؛ الوميض يعني قراءة تحتاج مراجعة أو خطأ.
- GPIO4: إشارة ترانزستور الصفارة.
- كل LED له مقاومة مستقلة 330Ω والكاثود إلى GND.

test-reader-feedback.cmd يختبر المخارج دون توليد حضور وهمي. نجاحه البرمجي لا يؤكد توصيل الإضافة فعليًا.

## 3. إعداد الفرع والواي فاي

شبكة الفرع الأساسي **JOESTOREJOESTORE** وشبكة فرع الجملة **Joe**. يحتاج ESP32 شبكة 2.4GHz. ملفات الهوية والمفتاح وكلمة المرور الخاصة هي:

```text
C:\Users\abdol\AppData\Local\JoeStore\Attendance\ReaderConfigs\branch1.h
C:\Users\abdol\AppData\Local\JoeStore\Attendance\ReaderConfigs\branch2.h
```

استخدم هوية القارئ الخاصة بالفرع نفسه. تغيير الفرع على جهاز عليه أحداث غير مرفوعة يحتاج مزامنتها أولًا؛ أحداث Bluetooth بهوية أخرى تُحتفظ بها ولا تُرسل من الفرع الجديد.

لأول إعداد شغّل setup-reader-wifi.cmd ثم ارفع الكود. لتغيير الشبكة بعد الرفع شغّل configure-readers.cmd والجهاز متصل USB. إعدادات NVS تتقدم على القيم المدمجة وتبقى بعد إعادة التشغيل، ولا يمسح تحديث الشبكة الطوابير.

## 4. رفع الكود

وصّل جهازًا واحدًا بكابل بيانات وأغلق Serial Monitor. حدد منفذ CP210x أو CH340 من Device Manager؛ منافذ Bluetooth ليست منفذ ESP32.

```powershell
Set-Location -LiteralPath 'C:\Users\abdol\OneDrive\Desktop\task\atendance_system'
.\scripts\flash-reader.ps1 -Branch branch2 -Port COM10 -Buzzer active -ArrivalLed green
```

استبدل الفرع والمنفذ بالقارئ الفعلي. الأداة تنسخ ملف الفرع الخاص إلى ملف مستثنى من Git وتبني وتفلش. إذا بقيت عند Connecting اضغط BOOT أثناء الاتصال ثم اتركه بعد بدء النقل. يوجد بيئة واحدة esp32dev ولا يوجد اختيار شاشة.

## 5. تشخيص USB

```powershell
& .\.tools\pio-runtime\Scripts\python.exe .\scripts\reader-usb.py --port COM10
```

التشخيص لا يحتوي كلمات مرور أو مفاتيح. تحقق من إصدار 1.4.0 والفرع الصحيح واتصال Wi-Fi والساعة والتخزين وRC522. حقول Bluetooth توضح الاتصال والبطارية والإشارة والمهلة وعمر الرصد وحالة المستقبل والطابور.

يمكن فتح Serial Monitor عند 115200 وإرسال --status. أغلقه قبل أداة USB أو الرفع. انتظر ساعة الإنترنت؛ لا يستبدل البرنامج وقت الالتقاط المجهول بوقت الرفع.

**لا تستخدم --format على جهاز عليه بيانات.** التهيئة مخصصة لجهاز جديد معروف أنه فارغ؛ تمسح الطابورين. البرنامج لا يهيّئ LittleFS تلقائيًا.

## 6. الاختبار الفعلي على Vercel

1. مرّر كارتًا غير مربوط: صفارة ثم وميض مراجعة بعد رد السيرفر. اربط UID بالموظف الصحيح وأعد المسح.
2. أول مسح داخل وقت الحضور: أخضر بعد اعتماد السيرفر ووقت المسح في اللوج.
3. مسح إضافي قبل فتح الانصراف: Refresh أصفر ووقت الحضور ثابت.
4. مسح بعد فتح الانصراف وبعد مهلة منع المسح السريع: أحمر؛ قراءة أخرى لا تفتح حضورًا ثانيًا.
5. اقطع إنترنت القارئ مع استمرار الكهرباء، امسح كارت اختبار، وأعد الشبكة: القراءة تبقى حتى ACK وتصل بوقت الالتقاط الأصلي.
6. اربط تاج الموظف من قسم Bluetooth وافتح جلسة حضور فعلية، ثم اختبر الابتعاد والعودة وفق [BLE-TRACKING.md](BLE-TRACKING.md).
7. الانصراف يطلب قواعد جديدة لإيقاف متابعة التاج. أثناء Offline يلتزم القارئ بالحد المعروف، والسيرفر لا ينسب رصدًا خارج جلسة الحضور للموظف.

النطاق اللاسلكي ليس مسافة دقيقة. نفاد البطارية أو إغلاق التاج يظهر «غير مرصود»، وتعطل المستقبل أو انقطاع اتصاله يظهر «غير معلوم». لا يتحول الرصد إلى خصم راتب تلقائيًا.
